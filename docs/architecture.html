SwitchBot → 気象庁 → LINE

雨アラートのしくみ

自宅にゲリラ豪雨が近づいたらLINEに知らせ、毎朝6時にはその日1日の雨の予報をグラフで送る。 そのために作った9つのファイルが、それぞれ何をしているかをまとめた資料です。

2026-08-23 Python GitHub Actions LINE Messaging API

01 — できること

このシステムがしてくれること

もともとの出発点は「SwitchBotで何か作れないか」でした。SwitchBot Hub 2にGPSは入っていないと分かったので、 自宅は動かないという当たり前の事実を使い、緯度経度を一度だけ調べて固定値として使う方式に落ち着いています。 座標そのものはコードには書かず、外から渡しています（理由は最後の注意点を参照）。

5分ごと 豪雨をつかまえる

自宅の半径1kmに強い雨が近づくと、降り出す前にLINEへ通知します。弱い雨と激しい雨で、通知の文面が変わります。

毎朝 6:00 1日の雨をグラフで見る

その日24時間ぶんの降水予報を棒グラフの画像にして送ります。傘が要る日かどうかが一目で分かります。

電源オフでもOK パソコンが要らない

GitHubのサーバー上で動くので、自分のMacやスマホが起動していなくても動き続けます。

02 — 全体像

システム構成図

左が雨のデータを提供してくれる場所、真ん中が自分で書いたプログラム、右が通知の届け先です。 矢印には「何が流れているか」を書いています。

03 — ファイル

どのファイルが何をしているか

全部で9つ。「実際に処理をするファイル」「覚えておくためのファイル」「設定を書いたファイル」の3種類に分かれます。

rain_alert.py処理 — 中心
このシステムの司令塔。2つのデータ源から雨の強さを取り寄せ、どちらか強い方を採用し、 しきい値（1mm/h と 20mm/h）と比べて通知するかを決め、LINEへ文章を送ります。 自宅の緯度経度やしきい値も、このファイルの上部にまとまっています。
jma_nowcast.py処理 — 気象庁担当
気象庁のナウキャストには数値で答えてくれるAPIが無く、地図の画像としてしか配信されていません。 そこでこのファイルが、緯度経度から画像のどの位置かを計算し、そのピクセルの色を読んで雨量に変換します。 自宅の1点だけだと隣町の豪雨を見逃すため、半径約1kmぶんを調べて一番強い値を採用しています。
daily_summary.py処理 — 毎朝担当
24時間ぶんの降水予報を取得し、棒グラフの画像を作ってLINEへ送ります。 雨の強さで棒の色が変わり（灰色＝ほぼ降らない／青＝雨／赤＝豪雨）、しきい値の位置には点線が引かれます。
rain_alert_state.json記憶
前回いつ通知したかだけを書いた小さなメモです。これが無いと、同じ雨について5分おきに何十回も 通知が飛んでしまいます。プログラムが自動で書き換えるので、人が触る必要はありません。
.github/workflows/
rain_alert.yml設定 — 時間割
GitHubに対する「5分ごとに rain_alert.py を動かして」という指示書です。 必要な部品を入れる手順や、書き換わったメモを保存し直す手順もここに書いてあります。
.github/workflows/
daily_summary.yml設定 — 時間割
同じく「毎朝6時に daily_summary.py を動かして」という指示書。 グラフの日本語が文字化けしないよう、日本語フォントを入れる手順も含まれています。
requirements.txt設定 — 部品表
プログラムが使う部品（ライブラリ）の一覧。通信用の requests、画像を読む Pillow、 グラフを描く matplotlib の3つです。GitHubはこの表を見て、実行前に部品をそろえます。
.env設定 — 秘密（自分のMacのみ）
LINEやimgbbの合言葉（トークン）と、自宅の緯度経度を書いたファイル。 他人に渡ると自分になりすまして通知を送られたり、自宅の場所が知られたりするため、 GitHubには絶対に上げません。クラウド側では代わりに、GitHubの「Secrets」という 暗号化された金庫に同じ値を登録してあります。コード側は「金庫から受け取る」とだけ書いてあります。
.gitignore設定 — 除外リスト
GitHubに上げないファイルを指定するリスト。.env をここに書いておくことで、 うっかり合言葉を公開してしまう事故を防いでいます。

04 — 順番

動くときの流れ

番号は実際に処理が進む順番です。2本の流れは互いに影響しません。

① 5分ごと 豪雨アラート
  1. GitHubが時間になったことに気づき、rain_alert.py を起動する。
  2. jma_nowcast.py が気象庁のタイル画像を取得し、自宅周辺の色を雨量に変換する。
  3. 同時に Open-Meteo からも15分刻みの予報を取り寄せる。
  4. 2つのうち強い方を採用する（見逃しを減らすため）。
  5. 20mm/h以上なら「豪雨注意」、1mm/h以上なら「まもなく雨」と判定する。
  6. メモを見て、前回の通知から十分に時間が空いていればLINEへ送り、メモを更新する。
② 毎朝 6:00 予報グラフ
  1. GitHubが daily_summary.py を起動する。
  2. Open-Meteo から、その日24時間ぶんの降水予報を取得する。
  3. 雨の強さで色分けした棒グラフの画像を作る。
  4. 画像を imgbb に預けて、インターネット上のURLをもらう。
  5. そのURLと「今日は傘が要るか」の一言を、LINEへまとめて送る。

05 — 中身

知っておくと分かりやすい4つのこと

気象庁のナウキャストは、雨の強さを色で表した地図として配信されています。 jma_nowcast.py は自宅の位置にあたるピクセルの色を読み、この対応表で数値に戻しています。 この資料の配色も、この気象庁のスケールから取っています。

なぜ2つ？

データ源を2つ使う理由

気象庁のナウキャストは細かくて速い代わりに、公式のAPIとして公開されているものではありません。 気象庁のサイトが内部で使っている配信を借りているので、将来仕様が変わって使えなくなる可能性があります。 そこで Open-Meteo を保険として並べ、片方が止まってももう片方で動き続けるようにしています。

なぜ間隔をあける？

同じ雨で連投しない工夫

5分ごとに動くので、雨が1時間降り続ければ12回判定されます。そのたびに通知したら邪魔なだけなので、 一度送ったら一定時間は黙る仕組み（クールダウン）を入れました。 ただし弱い雨と豪雨は別々に管理していて、小雨の通知直後でも豪雨は必ず届きます。

実際にあった不具合

時差という落とし穴

GitHubのサーバーは世界標準時、天気データは日本時間で返ってきます。これをそのまま比べていたため 9時間ずれて雨を全部見逃す状態になっていました。自分のMacは日本時間なので気づけなかったものです。 世界標準時の環境を再現して不具合を確認し、時刻の扱いを日本時間に統一して直しています。

なぜ画像を外に置く？

グラフがimgbbを通る理由

LINEに画像を送るときは、画像そのものではなく画像のある場所（URL）を伝える決まりになっています。 LINE側がそのURLに画像を取りに行くしくみです。作ったグラフはクラウド上に一時的にあるだけでURLを持たないため、 imgbbという無料の置き場所に預けてURLをもらっています。

GitHub Actions決まった時刻にプログラムを動かすサーバー公開リポジトリなので無制限に無料

LINE Notify は2025年3月末で終了しているため、後継の LINE Messaging API を使っています。 GitHub Actionsは1回の実行を1分単位に切り上げて計上します。実際の処理が27秒でも1分と数えられるため、 5分間隔だと月8,640分に達し、非公開リポジトリの無料枠（2,000分）では約7日で尽きます。 公開リポジトリに切り替えたのは、この制限を外して5分間隔を維持するためです。

07 — 注意

運用するうえで気をつけること

01
座標をコードに書き戻さないこと このリポジトリは公開されています（GitHub Actionsを無制限に無料で使うため）。 自宅の緯度経度は .env とGitHubのSecretsにだけ置き、コードには絶対に書かないでください。 一度コミットすると、後で消してもgitの履歴に残り続けます。
02
LINEの無料枠は月200通まで 毎朝のグラフが1日2通（画像＋文章）で月60通を使うため、豪雨アラートに使えるのは月140通ほどです。 雨の多い月に上限に達すると、その月はそれ以上送れなくなります（自動で課金されることはありません）。
03
実行間隔は5分（3分ではない） GitHub Actionsの定期実行は最短5分間隔が目安で、それより短く指定しても間引かれます。 気象庁のデータ自体が5分ごとの更新なので、情報の新しさは落ちていません。
04
通知が数分遅れることがある GitHub側の混み具合によって、決まった時刻から数分ずれて動くことがあります。仕様上避けられません。
05
気象庁側の仕様変更で止まる可能性がある 非公式の配信を使っているため、ある日突然データが取れなくなることがあり得ます。 その場合もOpen-Meteo側だけで動き続けますが、細かさと速さは落ちます。
